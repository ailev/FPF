# Domain Principle Frameworks

**Find a field's methods for the result you need.** These 36 frameworks explain domain practice through connected patterns, with conditions, worked cases and source grounds. Use them for a current task or as contributions to continuing development.

Together with FPF Core, these domain frameworks can provide the repertoire for a **shared human–AI culture of thinking and acting**, oriented toward open-ended development. Each field contributes its own methods and standards of judgement. Participants select and connect them for their work, develop the capabilities they need, and return useful improvements to the shared repertoire. The [Library Architectural Reference](../FPF-LIBRARY-REFERENCE.md#libraryreference13---a-canon-for-shared-humanai-culture) explains this cultural use.

If you know the field, choose a Suite or framework below. If you only know the difficulty, describe it in ordinary words and search the texts; [Using FPF Library](../USING-FPF.md#choose-what-to-read) explains how to find and connect useful contributions. The [Library introduction](../) gives the overall purpose and a first-use route.

This catalogue links to readable text on fpf.tools and to Markdown sources in the repository. GitHub previews can truncate large files. Check the [displayed source edition](https://fpf.tools/status) when the version matters.

## Combine only the contributions your work needs

Suppose a group choosing between two proposals needs a research finding, a local model and an explanation of how the model bears on the choice. A published finding may already apply. A modeling text may give a method that still needs local observations. An existing explanation may give the group the grounds it needs before the choice. If someone has undertaken to explain those grounds at the meeting, establish that they gave the explanation there. Use the relevant publications for what is still needed to make the choice or fulfil the undertaking.

When the purpose is to expand an agent's capabilities and continue to further attainable problems, use [Core's connected development method (C.40.OD)](https://fpf.tools/C.40.OD) with the relevant domain methods. The particular changes needed by a person, AI, team or organization differ.

Every full framework has one home in the Library. Using its methods elsewhere does not add a second membership. An embedded Framework Architectural Reference explains its pattern language; Suite References explain the larger disciplinary assemblies. The [Library Architectural Reference](../FPF-LIBRARY-REFERENCE.md) explains the boundaries and connections across them.
