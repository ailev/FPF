# Using FPF Library

Use this guide whenever your work relies on FPF Library methods, including when you develop or review the frameworks. Paths below are relative to the folder containing this file.

When configuring a software agent for a project, include this guide in its standing instructions. Attach the file or link it from `AGENTS.md` or the environment's equivalent. A link in a past conversation does not establish that the current performer can retrieve and apply it. Reuse a current reading while the instruction and access conditions remain unchanged; return to the relevant section when they change or the instruction is no longer available in working context.

When a referenced publication is present in this folder, resolve its pattern references in that copy, including references written as GitHub links. Use another edition when the task calls for an update or a comparison.

## Make the publications available

Check what the present environment can read and search. A GitHub link, a listed filename or a truncated preview is not access to the publication's full text. Some interfaces cannot retrieve a large publication through an attachment or connector. Do not assume that one interface's access limits apply to another.

Where the environment supports local files, obtain the publication files through an available download or repository checkout and use content search on those files. Keep this instruction with them. Where only excerpts can be supplied, obtain the complete relevant patterns or sections, including the conditions and dependencies needed for the question, and retain their publication names and pattern IDs. Use an accessible README, contents entry or search result to locate the needed material; the locator does not replace it. If the necessary passage cannot be obtained, state the missing access and keep the dependent conclusion open. You can continue work whose basis is available.

Establish the available publication set once, and update it when files or access change. The full distribution includes FPF Core, the Engineering, Management, Foundational Thinking and Human Capability Engineering DPF Suites, further domain frameworks, and the Architectural References for the Library and its Suites; a downloaded subset or one attached document offers less. The public `Readme.md` and Suite `README.md` files identify the publications. Search the available set together when the question might need contributions from more than one practice. A missing search result means that this search has not found an answer in those sources, not that the ecosystem lacks the method.

In the complete distribution, `FPF-Spec.md` and the [FPF Library Architectural Reference](FPF-LIBRARY-REFERENCE.md) are at the repository root. The [DPF catalogue](DPFs/) lists the Suite subfolders and standalone DPF files under `DPFs/`. This directory groups domain publications; it is not another Suite. The Architectural References explain which disciplines form each Suite and which are used across its boundaries. Using a framework from another Suite does not add it to the receiving Suite.

For development or review, use the edition and candidate selected by the assignment. Distinguish a proposed contribution from published guidance when reporting what the framework already supplies.

## Resolve a portable reference

A portable reference keeps the complete PatternID or SectionRef and enough context to recover the intended publication set and document. Add a document qualifier only when that identity is not already clear from the complete address and the context that travels with it. In this distribution the publication set is **FPF Library**. Its [document catalogue (Library.Reference:11.1)](FPF-LIBRARY-REFERENCE.md#libraryreference111---document-identities-and-current-carriers) associates declared DocIDs with their full titles and current files. Short navigation and usage publications can be named by their full titles without a DocID. A DocID identifies a whole document. Cite an embedded Architectural Reference within its containing document and name an edition separately.

For example, within FPF Library, HCD.12:4.1 locates a section of the Human Capability Development Principles Framework, and Library.Reference:9.1 locates the Library's explanation of connected development. Those complete addresses already identify their declared documents. Use FPF C.39:4.1 when a Core reference needs a document qualifier. These addresses have different structures; resolve each complete address under its declarations. Retain every suffix and every member or endpoint of a referenced list or range. Name a selected edition separately when its exact published content matters.

A whole-document reference can use its declared DocID or full title within the identified publication set. For an unnumbered heading, give its title and enough document context: Practical entries in HCD distinguishes that heading from the heading of the same name in Core.

First look for the declared document among the files available to you. Match its DocID and title, then search for the exact heading address and read the relevant section with its conditions. A GitHub hyperlink can help open a carrier, but its hostname and path are not required to identify the contribution. If local files are unavailable, search by the publication set, document title or DocID, and full local address through the web or an available search, fpf.tools or MCP interface. Check which publications and retrieval functions the available interface exposes.

Check that the returned text belongs to the intended document and contains the requested target. Keep the complete local address with any extracted fragment and restore any publication-set, document or edition context that will no longer accompany it. A search hit, similarly named pattern or newer edition is not a substitute for an unresolved target or a requested exact edition. State that limit and continue only work whose needed basis is available.

## Distinguish a source from material to apply

A citation such as “this distinction follows X” identifies the source the writer credits. If your grounds depend on the cited passage, establish what it supports and whether its conditions hold here. If the question is how the author arrived at the distinction, look for the passage or operation they actually used and how it entered their work. Another source may now justify the same conclusion even if the author worked from the first. Use the material already available when it settles the question.

For an instruction such as “use X to compare these arrangements”, establish whether X is required or suggested. A comparison already in hand can finish the work if it meets the order, including any terms about the method, the performer or a new performance. Otherwise make or obtain the comparison under those terms. You can use a known method directly where the choice is yours. If all that was requested was a reference, delivering the applicable reference can finish the task.

The same destination can serve either purpose. Ordinary wording should make the difference clear; short `Source:` and `Apply:` labels can help in compact lists but are not required. A contents entry or plain catalogue locator is only navigation. If a substantive reference is ambiguous, use FPF E.11.PUA:4.1.1 to decide what to read or apply. When writing such a passage, use FPF E.8:4.2.2.2 to make its purpose clear without redundant labels. An extract retains any necessary purpose or condition that would otherwise be lost with its heading or introduction.


## Keep the receiving work in view

Read the question before choosing the work. What could have the property, make the choice or undergo the change the recipient wants to understand? A text or a case can provide evidence about that subject. Check the starting instruction as well as the promised result. If readers must choose whose work matters or what material to investigate, show how to make that choice from the decision they face. Naming the participants or requiring a particular past incident in the first instruction can settle that choice for them. A worked illustration can use named people and a recorded case. Give the conditions that make those choices appropriate, so the reader can start elsewhere when the same commission calls for it. Before choosing an investigation, establish how its answer would serve the original work. [Choosing the question before the answer (C.39.QR:4.1)](FPF-Spec.md#c39qr41---recover-the-question-independently-of-the-proposed-answer). When a question turns on “at every level,” recover the relation, the domain and what is being asked of it. [Interpreting “all” in the original question](FPF-Spec.md#c39qr411---recover-what-all-covers). Apply [FPF C.39:4.1](FPF-Spec.md#c3941---state-the-local-result-and-try-the-cheap-exit) to establish what would let the recipient complete the work entrusted to them. Keep that use in view when the task already names a pattern, a source, a correction or a check. The named operation can supply only part of the needed result.

Use an adequate known answer directly. If a new or changed method is needed, use C.39:4.2–4.5 for methodological synthesis. Work out what each operation acts on. If one requires another’s result, trace what it needs from that result. If several contribute together, establish how their contributions fit under the conditions of the receiving work. A common constraint can determine what is possible even when neither operation supplies the other. When different source meanings change that choice, compare their consequences with F.0.2. That conceptual comparison can also answer an inquiry in its own right. E.4.CM develops the explanation for a maintained framework contribution. A task-local answer, an available supplier or a sufficient partial result may already meet the need.

When the question is what someone or something contributed, identify the result at issue and the relation the answer must establish. The work performed, a share credited and the difference a change makes can call for different grounds. [What did it contribute? (Library.Reference:6.1.1)](FPF-LIBRARY-REFERENCE.md#libraryreference611---what-did-it-contribute)

When you restate or delegate a question, use an illustration, or return a local result, recover the work the recipient needs from the original request. If the question has changed in subject, actor, choice or scope, or if the inference from the local result to the original use remains uncertain, use [C.39.QR](FPF-Spec.md#c39qr---return-results-to-the-original-question) to establish what the new result contributes and answer the remaining question. Use C.39.SA when you need to select the kinds of holons, scales of their composition, or levels of model abstraction for that work. A different question can be proposed to the recipient when there is reason to change the commission.

If that contribution is an account of an organized whole or broad field, use [C.39.WA](FPF-Spec.md#c39wa---develop-an-account-of-the-whole-subject) to develop its common grounds and relations, explain what they establish about the whole and follow their consequences for the parts. A checked extraction establishes what the source supplies; an explained general way may still require construction. A reader's private invention can reveal that need without establishing that the publication already supplies it.

Follow a source or dependency as far as the original question requires. For an explanation, give the relation that accounts for what the reader wants to understand and the grounds for applying it. Two accounts can warrant the same action while explaining an outcome differently. What they establish in common can suffice when the commission is to choose that action. When the commission is to design a way of working, show how its operations would produce the required result. When it includes execution, do the work or arrange it where delegation is permitted. Establish that the required result was produced or that the practice continues to operate under the agreed conditions.

When a proposed action or evidence demand has unclear value or feasibility, use [FPF C.11.DUA](FPF-Spec.md#c11dua---make-advice-and-evidence-demands-worth-their-burden) to compare what the demanded work can change with its burden and return warranted advice for the receiving decision. A binding requirement continues to govern until its authority or agreement changes it.

Apply these moves within the current work. Reuse the established receiving use and sound results while their conditions hold. After an interruption or a changed assignment, recover that connection before choosing the next local move.

When writing an FPF pattern, use [E.8, FPF Authoring Conventions](FPF-Spec.md#e802---what-this-buys) while choosing the practitioner’s question, the contribution and its reach. The initial incident can suggest a subject. The initiating need and the domain grounds determine whether the proposed explanation answers it. For an independent admission or refresh review of that pattern, [E.19:4.1](FPF-Spec.md#e1941---define-the-reviewed-pattern-or-subset) takes the reviewer back to the terms of the original commission before using the author’s proposed checks.

## Choose what to read

If a pattern is already named, find its body directly. Otherwise search the available publications together, using terms for the difficulty and needed result. Include English technical terms when the user's language differs from the sources. You can find an individual method or a connected application without first choosing a Suite, Reference or pattern file.

When sources or terminology are uncertain, [FPF F.1:4.4](FPF-Spec.md#f144---find-candidate-material-when-sources-or-terminology-are-uncertain) explains how to construct and adapt a search from the available access, preserve the original question, inspect candidates and return consequential limits. Use F.1's source-selection branch when a justified basis over several sources is needed. A sufficient known source can be used directly.

Inspect a promising passage with its enclosing heading. A pattern body supplies its method; a Reference answer can explain how several contributions work together; a README or contents row helps locate that explanation. Open the substantive source and the conditions needed for the present use. When exploring the repertoire without a useful search phrase, start with Core Part headings or the corresponding Suite overview, then retrieve selected entries. Search a large Table of Contents as text and read the matching rows; do not load it in full merely to begin a lookup. Its technical terms, practical questions and dependencies can help reformulate the search.

Apply a familiar method directly where its known conditions hold. To learn how it works, check its applicability or use a specified edition, consult the description and the related sections the task needs. Read the specified material afresh when that reading is itself commissioned. For a particular technique, use its section with the conditions on which it depends. Apply it to the facts and constraints of the task. If a candidate method presupposes a result you still need to obtain, search for that earlier result or operation rather than silently treating it as given. For example, resolving a known conflict does not by itself explain how to notice a difficulty in ordinary work. A later method's scope limit is not evidence that the earlier contribution is absent from the framework.

If a pattern includes a conformance checklist, use it to inspect the result. Where a required part is missing, use the relevant operation in the method to obtain it.

Explain results and give feedback in the language of the project's work. Preserve the source distinctions that affect the answer. Cite the patterns and locations used. State assumptions, gaps in the evidence and limits on use where they change what the recipient can explain, conclude or do. If the decision needs a particular judgement, identify who can provide it and any authority required to act on it. Let the current question determine the next step.

When a question needs several methods, look for an explanation of how to use them together in a pattern or Architectural Reference. A connected example or Practical-Use Card can help you find and understand that explanation. Follow the needed result through the contributing methods. Identify who uses whose result, which contributions must hold together and which changes can require a different choice. An overall result can depend on several contributions made in either order. A mantra helps retain that connection. Choose the next contribution for what it would establish, supply or accomplish for the recipient’s original commission. A separately ordered performance can still be due when its likely result is known. Among contributions that serve the commission, the inputs already available can help determine which one to undertake first. If one method's result leaves the larger work unresolved, search the same publications for that larger result together with the method's ID or useful terms. Continue through the connected account only where it supplies a contribution the work still needs. An adequate earlier result or a sufficient individual method can end the lookup.

When composition matters, start at the scale and in the kind of holon the question concerns. To explain work that has taken place, establish which performances belonged to it and what they achieved together. B.1.5.EW helps recover the enclosing Work from a known action and the constituent performances from the whole. To design future work, start from what its recipients must obtain. Work back to the contributions needed, how their results can be used together and what conditions the design must secure. This can support a design before the first performance. An order to select a replacement for a constituent can use B.1.5.RS. In either direction distinguish composition of the Method from composition of an actual performance of it. Across the scales the commission concerns, retain the distinctions that can change the recipient’s action or explanation. For example, two assessments may have to concern the same edition, or otherwise independent commitments may draw on a shared resource.

When these facts change which alternative continuation is available, use A.22.CGUS:4.1 to distinguish available, blocked and unknown continuations from their conditions, and return that judgement to the present choice.

Explain the connection in the language of the work. C.30.ASV:4.5a helps distinguish the relevant structures when the work depends on how the parts, activities or models are related. If a drawing uses vertical or horizontal direction, name the represented structure and relation as A.22:4.3a explains. A diagram is optional.

## Learn the contribution the work needs

Using a method to obtain a result and learning to perform it are different purposes. Decide which contribution you need to make yourself and which can be supplied by a source, tool, specialist or AI assistant. For example, you may need to interpret a model's limits even when another contributor builds and runs it. The answer can meet today's need. For a decision about later work, identify what the performer must do and what help will be available. Earlier work can already show that the performer made the required choices under comparable conditions. When the conclusion depends on a change of situation, establish why the ability carries over or examine what the performer can do under the changed conditions. [Library.Reference:9.3.1](FPF-LIBRARY-REFERENCE.md#libraryreference931---a-shared-repertoire-with-different-holders-and-different-claims) distinguishes an individual contribution from what a team can do together.

When the question is how to help, start from the result the recipient needs. Direct delivery, shared work, restoring access and developing a capability can each meet a different need. Identify what the recipient must still do and what help will actually be available. Follow [Library.Reference:9.2](FPF-LIBRARY-REFERENCE.md#libraryreference92---help-enablement-and-the-organization-of-professional-support) when that choice remains open.

When the goal is a person's learning, use the [Human Capability Development DPF (HCD)](DPFs/Human%20Capability%20Engineering%20DPF%20Suite/HUMAN-CAPABILITY-DEVELOPMENT-PRINCIPLES-FRAMEWORK.md). HCD.1–HCD.3 connect later work, current preparation and the choice of development or support. HCD.9 guides practice with feedback and correction; HCD.10 helps vary it for the missing operation. HCD.12 distinguishes evidence of applying an already learned method under a changed condition from evidence of learning a new method with a source. HCD.15 reopens development when the work or its support changes. Read only the contributions needed for your question; the order of publications is not a requirement to learn every method first.

When the intended performer is an AI agent, [Library.Reference:9.3.4](FPF-LIBRARY-REFERENCE.md#libraryreference934---ai-acquisition-requires-a-change-in-available-execution) explains how to change its working configuration and check what it can do in later use.

## File structure

A publication contains several patterns, located by their IDs. For example:

| Markdown | Meaning |
| --- | --- |
| `## SYSE.24 - Choose How the Project Will Obtain a Needed Engineering Result` | Start of pattern `SYSE.24` |
| `### SYSE.24:4 - Solution` | Section of that pattern |
| `#### SYSE.24:4.1 - Name one result and one decision` | Subsection |
| `### SYSE.24:End` | End of the pattern |

IDs also occur in contents tables and cross-references. Match a heading at the start of a line to locate the pattern itself. Line numbers help retrieve portions of a file; IDs locate a pattern after its line numbers change. A reference such as `SYSE.24:4.1` points to a subsection; read it through to the next heading of the same or a higher level.

## Search and read

Use `rg` (ripgrep), or the environment's equivalent search tool with regular expressions. Run these commands with the public distribution folder as the working directory, or prepend its path to the file arguments. In a source repository, limit the search to the selected public publications; campaign notes and historical drafts are not the public corpus.

The examples below use `.` for the public distribution root. In a source repository, replace that operand with the selected publication files or directories in each command. For example, use `FPF-Spec.md FPF-LIBRARY-REFERENCE.md DPFs` when these are the selected public carriers.

Inspect the available Markdown files once to establish the search scope. This lists filenames; it does not search their contents:

```sh
rg --files --no-ignore -g '*.md' .
```

For the illustrative question “obtain a needed engineering result: build or buy”, search the text across that scope:

```sh
rg -n -i -C 2 --no-ignore -g '*.md' -- 'build or buy|obtain a needed engineering result|obtain climate control' .
```

This query can return a pattern, a contents row and a connected Reference case. Compare the question each passage answers, open its enclosing section and retain the useful result or return condition. If the output is too large, use the same query with `-l` instead of `-n -C 2` to list matching files, then inspect promising passages. Reformulate an unsuccessful query; a lexical match alone does not establish fit, and no match does not establish that the method is absent.

A browser or retrieval system can serve the same search when it covers the declared publications, including Reference answers. If it exposes only one file or titles, state that limit and extend access when the question requires it.

Locate the file and the start and end lines of the selected pattern:

```sh
rg -n --no-ignore -g '*.md' '^## SYSE\.24 |^### SYSE\.24:End[ \t]*\r?$' -- .
```

Read that pattern in full:

```sh
rg -U --no-heading --no-line-number --no-filename --color never '(?ms)^## SYSE\.24 [^\r\n]*\r?\n.*?^### SYSE\.24:End[ \t]*\r?$' -- "DPFs/Engineering DPF Suite/SYSTEMS-ENGINEERING-PRINCIPLES-FRAMEWORK.md"
```

Here `-U` enables multiline search; `(?m)` makes `^` and `$` match line starts and ends, and `(?s)` lets a dot match a newline. `(?ms)` combines them. `.*?` matches through to the nearest specified `:End` heading; `\r?\n` accepts Windows and Unix line endings. Substitute another ID and file as needed; escape literal dots in IDs as `\.`.

For other searches, `-F` treats the query as literal text, `-i` ignores case, and `-C 2` includes neighbouring lines. `--no-ignore` searches files even in a Git-ignored folder; `-g '*.md'` selects Markdown files.

If the tool truncates a long result, read the selected text in successive line ranges with the available file reader. Folder search already covers separate publications; no combined file is needed.
